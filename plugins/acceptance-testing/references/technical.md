# 技术测试选择

| 能力 | 适用触发 | 核心断言 |
|---|---|---|
| 静态/构建 | 相关源代码、配置或发布产物改变 | 编译/类型正确，构建可用；命令成功不等于业务正确 |
| 单元/组件 | 计算、校验、状态与交互变化 | 正常、边界、无效输入与错误分支，不照抄实现 |
| 集成 | 数据库/缓存/队列/存储连接或行为变化 | 事务回滚、消息处理、真实依赖配合、持久化 |
| 接口/契约 | 客户端与服务协议变化 | 请求响应、错误码、分页、字段兼容与双方约定 |
| 数据 | 更新、迁移、批处理、导入导出变化 | 约束、防重复、并发更新、前后数据一致 |
| 权限/安全 | 身份、角色、租户、文件输入变化或明确安全验收 | API 直接越权、跨租户访问、会话失效、输入风险 |
| 性能/容量 | 明确负载目标、资源瓶颈或发布要求 | 固定环境/数据规模/负载下响应、错误、吞吐与资源；无目标不随意压测 |
| 异常/恢复 | 重试、后台任务、第三方依赖、中断风险 | 超时、限流、重启、重复回调后的结果一致性 |
| AI 评测 | 产品自身含模型/Agent 且相关行为改变 | 固定样本、质量、工具正确性、失败路径、延迟及总成本 |

冒烟是深入测试的前提子集，回归按影响选取。优先多次可重放且便宜的明确断言；UI 核心链路仍需实际用户入口。已有测试读取其断言与覆盖，不因名称叫 integration 就认定它使用真实数据库。

## 重要陷阱

- HTTP 200 和“提交成功”不足以证明保存正确；必要时核验数据/其他角色结果。
- schema 检查不等于调用双方契约验证；外部依赖模拟通过不等于真实服务通过。
- 依赖扫描不代替权限与数据隔离用例。
- 测试覆盖率/总通过率不是发布充分条件。关键要求未覆盖单列。
- 执行框架 skip、xfail/expected failure 或 flaky 不作为必需业务断言稳定通过。
- 新增 tests 在冻结前完成；修改被测代码或断言后新轮。数据生成或测试输出目录不得纳入源代码假变更，明确放在档案/被排除产物目录。

技术方法参考：ISTQB 基础纲要 https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf；安全要求可按需参考 OWASP ASVS https://owasp.org/projects/asvs；性能阈值 https://grafana.com/docs/k6/latest/using-k6/thresholds/ 。版本与本项目适用性需核对，不每轮重复联网调研。
