# 交付适用性

本地日常开发以材料发现风险，部署与恢复演练仅在目标需要时执行。第三方接手先核对依赖、脚本、配置和已有记录，再提出最小补齐路径。

## 环境与复制

| 承诺/风险 | 取证方法 |
|---|---|
| 独立安装 | 干净隔离环境按说明完成，记录时间、人工干预及遗漏 |
| 配置迁移 | 不依赖个人路径/账号，凭据外置，配置清单可复制 |
| 初始化重放 | 再执行不重复数据、不损坏状态；生产清理不可擅自做 |
| 内网/离线 | 在承诺的网络与依赖源条件实测；容器不能自动证明离线可用 |
| 资源约束 | 启动、空闲、常规、峰值资源及适用负载 |
| 升级回退 | 使用旧数据验证升级与失败恢复，说明回退的数据限制 |
| 备份恢复 | 实际恢复并核验业务数据，不能只看备份文件存在 |
| 第二次交付 | 独立环境/客户配置重跑，统计新增工作及定制 |

## 必要性审查

对主要组件列：需求来源、移除后果、部署/监控/升级成本、故障影响、替代路径。发现职责重叠、特殊启动顺序、无目标的预先扩展、单点依赖、每客户改代码时，给具体例证和保留/局部简化/替换选项。不根据流行度或组件数量打分。

## 四笔成本

首次交付：安装配置、迁移、账号开通、培训。持续运行：基础设施、存储流量、模型与第三方、空闲固定支出。维护支持：监控、升级、排障、恢复与人工接管。新增客户：独立部署、配置、定制及持续支持。

成功任务平均成本 = 同一批次相关调用（含失败重试）+ 分摊基础设施 + 人工处理成本，除以成功任务数。单价、负载、成功率、人工假设与来源分别记录；没有预算或负载目标时不武断判贵/便宜，也不从技术测试推断市场需求或商业盈利。

商业交付相关时记录账号归属、服务可获得性、数据导出与需核查的许可/条款，避免无依据法律判断。
