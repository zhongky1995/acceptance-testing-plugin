# 业务用例设计

从“角色 → 触发 → 输入/前置 → 规则 → 操作 → 可见反馈 → 最终结果 → 异常恢复”形成任务。系统调用成功、用户任务成功和业务最终成功分别定义，超出产品责任终点的结果不承诺。

## 有用的方法

- 等价类：空、合法、非法、特殊类型代表值。
- 边界值：允许 1..10 项时测 0/1/2/9/10/11，按风险选择。
- 决策表：角色、金额、状态、时间等条件组合；高风险组合完整覆盖，普通组合可选代表。
- 状态迁移：允许/禁止转换，撤销、驳回、重提、过期、批量部分成功。
- 探索：带目标尝试刷新、回退、快速重复、输入中断、异常提示与恢复；记录实际操作和发现。

## 审批示例

正常申请与处理；信息缺失；普通员工直接调审批接口；管理者审批本人申请；两位管理者同时处理；重复提交；处理中断再进入；申请人/审批人/审计记录一致。不是每轮都执行全部，根据改动、风险和证据选择。

## Computer use 与稳定自动化

先检查宿主当前可用能力，不因为安装本插件就假定 computer use 存在。首次使用遵守工具当前文档。稳定 UI 流程可转为已有浏览器框架回归；不把“探索”无限重复。

实际执行从约定入口开始。核验截图、页面/可访问性状态、请求或后端结果；有需要时等待业务完成，而非只等待按钮点击。记录前置账号、步骤、实际结果和失败恢复；观察记录必须来自真实工具执行，不用 AI 生成截图代替。

不同浏览器/模型/环境按承诺矩阵选测。体验意见写明依据及主观性；最终真实工作适配由业务负责人确认。对外消息、支付或其他真实影响须在测试授权内，用沙箱/测试数据优先。
