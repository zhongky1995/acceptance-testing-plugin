# 交付评估

读取 [交付检查与成本方法](../../references/delivery.md) 和 [场景规则](../../profiles.json)。先以材料与现有运行记录发现风险，只有影响本轮目标时再投入环境搭建或实测。

- 第三方预检先核对文档、启动/构建脚本、依赖声明、配置和已有证据；不因为代码来自第三方就安装全部依赖。
- 新环境与正式交付按实际承诺验证干净安装、配置迁移、可重复初始化、升级/回退、备份恢复和第二次交付；记录人工干预、时间、特殊步骤及失败原因。
- 每个主要运行组件说明需求、移除影响、部署/维护负担及可行简化路径。不能以组件数量、流行程度或目录形式直接断言冗余。
- 故障恢复、资源和成本结论须有适用负载与环境。静态风险、实测事实和待验证假设分别标记。
- 成本至少区分首次交付、持续运行、维护支持、新增客户。AI 成功任务成本包含失败重试及人工处理；缺少规模/预算时报告结构与敏感项，不能虚构价格或盈利判断。
- 依赖和许可/服务条件可能影响交付时列核查项，不作无依据的法律结论。市场需求与定价接受度不由技术验收推导。
- 需要实际演练的项写入本轮用例，由执行工具记录；没有演练就标本轮未验证，不写“已验证可复制”。

分别报告功能、环境、复制、稳定性与成本，提出保留/简化/替换的适用选项。未授权不重构产品、创建云资源或部署到生产。
