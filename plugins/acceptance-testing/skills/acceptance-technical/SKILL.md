# 技术验证

读取 [技术检查](../../references/technical.md)、[工具适配](../../references/adapters.md) 及 [数据合同](../../references/contracts.md)。若尚无明确本轮标准和计划，先补必要规划，不直接选一整套工具。

- 复用项目原有框架、依赖、服务与测试数据。只启动实际需要的环境；缺失依赖先列明受影响范围和最小准备成本。
- 项目脚本可能有副作用；执行前读取相关脚本和配置，正确声明安装及外部调用。CLI 的声明检查不构成网络或系统沙盒。
- 使用真实行为断言：业务输出、权限拒绝、持久化、事务恢复等。不能仅检查函数存在或照抄实现逻辑。
- 测试结果使用结构化适配器，写进本次 `{evidence_dir}`。JUnit 可承接已有框架；Playwright JSON 可承接浏览器回归；简单专用断言可输出 native 格式。适配命令参考 adapters.md，运行前核对本项目版本。
- 环境与测试脚本失败应区分，不能都归咎产品。超时需定位原因，预算达到上限即保存。
- 根据依赖排序；依赖未满足只阻断关联项。技术和业务验证共用要求来源，不替业务技能推断任务成功。
- 同版本复核使用保留尝试的重试。代码修复后新建一轮记录，用失败用例与相关回归取得新证据。

输出技术结果、复现线索、证据及未测范围。未经用户授权不修改业务代码、删除用例或降低断言来获得绿色报告。
