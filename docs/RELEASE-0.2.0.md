# v0.2.0 · 交互验收与程序防漏

本版将能力实现、需求适配、交互与可用性分开验收。不同 Agent 通过统一执行工具和持久化档案继续工作；后端测试通过不能代替需求与交互验收。插件运行仍仅依赖 Python 3.10+ 标准库及宿主已有工具，采用 MIT 许可证。

## 本次更新

- 新增「交互验收」技能，共七个按需技能。检查用户入口、理解、动线、反馈、完成和异常恢复，并记录常规交互模式的适用依据。
- schema 1.1 从关键用户任务推导必要检查点；缺失用例、漏步骤、未判断状态适用性或把必要检查改成可选，均不能满足产品门禁。
- 交互观察先核对同一任务的需求与路径基线。单次检查记录绑定方案、项目快照、环境、用例和尝试次数，逐点关联预期、实际、证据及操作轨迹。
- 新增 `readiness` 缺口检查和 `gate` 放行命令。限定范围的 focused 检查不会被当成 product 整体验收通过。
- 报告分别展示三类结论与各检查点的实际结果；部分点通过不改变整条必需用例失败或不稳定的结论。失败后重试成功仍保留不稳定记录。
- 统一档案支持不同 Agent 接手，保留已有执行、证据、预算占用及失败记录，无需依赖聊天记忆。

## 升级注意事项

0.1.x 的 schema 1.0 档案仍可生成历史报告，但不能在新版继续执行或获得新版整体通过。请保留原档案，新建 schema 1.1 轮次，复用需求材料并补齐本轮执行证据；不要直接改旧档案的版本字段。

安装固定发行版本：

```sh
codex plugin marketplace add zhongky1995/acceptance-testing-plugin --ref v0.2.0
codex plugin add acceptance-testing@acceptance-testing-local
```

已有同名来源时，通过客户端更新或切换来源版本，再更新插件，避免重复添加。安装和更新后在新聊天使用。完整方法见 [v0.2.0 README](https://github.com/zhongky1995/acceptance-testing-plugin/blob/v0.2.0/README.md)。

## 已完成验证

- 73 项离线测试在 Python 3.10 和 3.14 上通过；其中 37 项覆盖新增协议与防漏规则。GitHub 自动检查同时运行隔离审批演示和打包校验。
- 七个技能通过静态校验。真实浏览器走查检出隔离样例中的本人审批缺陷，并保留截图、界面状态与逐点证据。
- 验证没有新增运行依赖或调用被测项目的付费服务。详细记录见 [验证说明](https://github.com/zhongky1995/acceptance-testing-plugin/blob/v0.2.0/docs/VERIFICATION.md)。

## 能力边界

程序检查已声明范围内的流程、覆盖和证据关联，不能独立证明语义判断、身份声明或业务效果真实。界面线索扫描不能保证发现全部用户任务；Agent 走查不能替代真实用户研究。发布或交付端必须接入 `gate` 结果，才能拦截其后续动作。本地插件不能约束外部流程绕过门禁或同权限恶意篡改。
