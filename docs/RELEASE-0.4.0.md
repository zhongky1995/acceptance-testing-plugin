# 0.4.0 — 强制合并保护与通用项目 CI

增加可复制到项目仓库的分层 CI 模板，使日常改动自动运行必要检查，相关风险触发集成或界面回归，完整交付另外检查本轮产品验收。插件自身仓库启用 GitHub 强制合并保护。

## 本次变化

- `qa_ci.py init` 生成标准库执行器、风险配置、同版验收内核和 GitHub Actions 模板；已有 CI 可用 `--runner-only` 并入原流程。同名文件停止，不覆盖定制。
- 基础检查每次运行；集成/契约和体验回归按实际目录选择；交付需手动选择。缺失基线、未知路径或 CI 配置变化扩大自动覆盖，重命名同时检查旧新路径。
- 固定检查名 Acceptance CI，工作流不做 paths 过滤或条件跳过。空命令、缺工具、超时、较早失败都阻断并停止更深投入；报告区分未触发、不适用和因失败未执行。
- 默认累计预算 480 秒，单命令超时、无自动重试、单执行作业、浅克隆、取消过时运行。模板无模型 API 依赖或付费服务密钥，复用项目原有环境；GitHub 分钟费用仍按账号规则计量。
- delivery 模式在项目命令之后强制调用原 qa.py 产品 gate；局部检查、只有技术自动检查或旧版本证据都不能充当产品通过。
- 增加实际契约回归演示、项目接入指南、README 与技能路由。验收 schema 仍为 1.2，CI 配置独立为 1.0。

## 仓库合并保护

main 的必要检查为 validate (3.10)、validate (3.14)，来源绑定 GitHub Actions；strict 要求跟上主分支，管理员也受约束，要求 PR 合并，禁止强推和删除 main。保留个人维护可操作性，不要求另一位维护者审批。保护是 GitHub 设置，其他项目按指南配置自己的 Acceptance CI，不会自动迁移权限。

## 验证

- 127 项离线测试在 macOS/Python 3.10.19、3.14.6 上通过，其中 25 项为新 CI 路径、失败处理和产品 gate 接入检查。
- 覆盖真实 Git 重命名/删除/空格路径、未知基线/目录、按风险选择、空配置、不适用依据、外部副作用声明、失败停止、超时、缺命令、报告保护、独立进程运行、缺失/局部/完整/过期产品证据。
- 新演示对说明变更只运行 fast；消费契约出现真实边界回归后，普通输入成功但 integration 阻断。原有审批、契约演示继续保持预期结果。
- 七技能静态验证、Markdown 引用、工作流 YAML 解析和打包校验通过。新增演示接入插件的双版本 GitHub CI。

测试中的产品观察是明确标注的合成协议夹具，不代表真实用户验收或所有技术栈已经接入。模板的路径及命令需要按项目配置，副作用声明不是网络沙盒；付费专项另行使用验收预算安排。自动检查信号不等于产品效果，模板也不自动部署。

## 安装与升级

更新插件到 v0.4.0，已有 schema 1.2 档案继续按原标准使用。首次项目 CI 接入见 [项目 CI 指南](../plugins/acceptance-testing/references/ci-integration.md)；已有 CI 优先 runner-only，避免重复流水线。项目中的生成副本由项目控制，插件更新不会覆盖它们；升级副本时在临时目录生成并审阅差异。

提供插件 ZIP、Codex 来源 ZIP 和 SHA256SUMS，MIT 许可证保持不变。
