# 0.3.0 — 风险样本、契约、逐步证据与计量约束

此前的程序可以检查已列用例和检查点，却仍可能遗漏边界输入，把其他步骤的观察对应到当前步骤，或将一次成功描述为产品稳定。0.3.0 使用 schema 1.2，把这些约束放入共同执行内核，所有宿主使用相同记录和门禁。

## 新增

- 五类风险适用性必须逐项声明，适用变体由程序推导；样本绑定输入内容摘要，同内容换编号不增加代表性。局部检查可明确延期，产品验收不能隐藏适用风险。
- contract 适配器核对同一输入在真实生产方与消费方的判断。每个声明边界都要覆盖合法、上界、拒绝输入；生产接受而消费拒绝必失败，不信任单个 passed 标记。
- check 生成冻结的逐点预期与绑定，交互步骤绑定具体动作及反馈，每个样本有独立原始位置和轨迹对应。复用原始文件仍需逐点定位，不能跨用例复制绑定。
- 结论区分 single_run / representative / sustained；single_run 不获得产品验收通过。代表性至少覆盖声明矩阵与每任务各必需层面的不同输入，持续性另要求实际次数及窗口；都不保证未来可靠性。
- 外部请求、token、费用和失败调用纳入账本。check 预留预算，多个待执行观察不能重复占用同一份余量；未知费用不记作免费，复用同一请求按显式引用计一次。
- 观察时长采用程序记录窗口与宿主声明的较大值，报告区分命令执行、观察等待和未计量的宿主规划开销。增加无付费调用的契约缺陷及修复演示。

## 保持轻量

继续只依赖 Python 3.10+ 标准库、项目与宿主已有能力。没有新模型 API、数据库、常驻服务或自动依赖安装。默认复用本地资料及离线/录制样本，不自动执行组合穷举、持续监控或收费压力测试。

不同语言通过现有项目命令提供小型适配器即可。接口适配器需要调用真实两端，不能重新实现一套假规则。详细字段与可运行例子见 [风险与证据协议](../plugins/acceptance-testing/references/assurance.md)。

## 验证

- 102 项离线测试在 macOS 的 Python 3.10.19 与 3.14.6 通过，含原有 73 项及新增 29 项反例/正向检查。
- 覆盖风险缺项、遗漏上界、重复样本、缺少实际样本回执、契约错配、错步骤/跨用例绑定、逐样本轨迹缺失、单次结果扩大、未达到持续窗口、请求遗漏/重复/未知/失败、预留与显式复用、观察零耗时、旧协议限制及账本回读。
- 审批与契约两类隔离演示均先发现实际缺陷，在修改隔离副本后新轮通过。契约示例的普通输入通过、合法上界被下游拒绝，修复后接受。
- 七个技能静态校验通过，文档引用和发行打包校验通过。GitHub 的 Python 3.10 / 3.14 自动验证见仓库 Actions。

这些验证证明执行协议与离线样例，不等于多个模型实际遵循测试、真实客户验收、性能压测或收费服务验证。没有把旧版本的浏览器取证记作本版新证据。程序不独立证明截图语义、完整需求或声明真实性，也不是网络沙盒或防恶意篡改系统。

## 升级

保留既有档案，将插件更新到 v0.3.0，用 init 新建 schema 1.2 轮次。schema 1.0/1.1 仅用于历史解释，不能继续执行或直接获得新版 product 通过。复用产品材料和离线输入，补齐风险、样本、证据绑定和账本；不要修改旧 schema 字段冒充升级。

报告重新生成会写 report.md/report.json；如需保留旧报告，在档案副本上做历史复核。插件升级本身不修改项目档案。

提供插件 ZIP、Codex 来源 ZIP 及 SHA256SUMS。MIT 许可证不变。
